# Technical documentation review checklist

This checklist is based on practical documentation review principles. It is not an official Microsoft certification.

## Source and technical accuracy

- Confirm the source inventory, version, authority, and access coverage.
- Verify each material claim against its original source. An exact quote does not by itself prove the claim.
- Separate requirements from tested implementation behavior.
- Check UI labels, permissions, defaults, prerequisites, state changes, errors, and recovery.
- Do not invent endpoints, parameters, response fields, or results.
- Record unresolved contradictions and missing information. Block unsafe steps.
- Identify sensitive information, irreversible actions, and privacy risks.

## Task quality

- Start with a clear reader goal and supported prerequisites.
- Use imperative, focused steps with meaningful outcomes.
- State the expected result where the source supports one.
- Confirm code examples or label them as untested illustrations.
- Distinguish conceptual content, task procedures, reference, and troubleshooting.

## Style and accessibility

- Follow the supplied house style, then applicable Microsoft Writing Style Guide principles.
- Use consistent terminology and sentence-style headings.
- Prefer direct, active sentences and descriptive link text.
- Use accessible tables, meaningful image alternatives, and text descriptions for diagrams.
- Avoid ambiguous dates, times, units, idioms, and unsupported platform assumptions.

## Approval

Record who reviewed the source fidelity and whether they were independent from the drafter. Record product verification separately. Only an authorized human can approve publication. A passing automated checker is not publication approval.
